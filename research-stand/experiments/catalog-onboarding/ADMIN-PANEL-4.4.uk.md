# Хронометраж ручного підключення Catalog через Admin Panel

Підключіть Admin Panel до Gateway ізольованої копії. [Запуск і адреса Gateway для панелі](../../../admin-panel/README.md).

Виконайте 3–5 повторів однією людиною на ізольованій копії стенду. Вимірюйте активну роботу з формами та очікування їхніх відповідей одним секундоміром. Для кожного повтору використовуйте той самий браузер, ті самі підказки та однакові правила копіювання значень.

1. **До старту.** Запустіть Catalog у профілі `expanded`, дочекайтесь реєстрації в Eureka. Manager має бути в OBSERVE. Підготуйте роль `ROLE_EXPERIMENT_WRITER`, звичайного користувача й користувача з цією роллю. Перевірте, що прив’язка дозволу `catalog.write` до ролі порожня. У тестовій конфігурації Auth відсутній `catalog-service`, у Gateway відсутні його маршрути, запит до `/catalog-service/products` повертає 404. Увійдіть адміністратором та відкрийте список сервісів. Підготовка поза хронометражем.
2. **Старт секундоміра** — безпосередньо перед натисканням **«Створити сервіс»**. Введіть `catalog-service`, натисніть **«Зберегти сервіс»** та відкрийте створений сервіс.
3. **«Створити маршрут»**. Виберіть `catalog-service`, шлях `/catalog-service/**`, порядок `0`, звичайний сервісний маршрут. Для публічного читання приберіть запропонований формою фільтр `Authentication`, залиште ролі порожніми. Натисніть **«Додати предикат»**, виберіть `Method`, параметри `{"methods":"GET"}`. Підтвердьте конфігурацію і збережіть маршрут.
4. Створіть другий маршрут із тим самим сервісом та шляхом, порядок `1`. Укажіть `Method` з параметрами `{"methods":"POST,PUT,DELETE","_genkey_0":"POST","_genkey_1":"PUT","_genkey_2":"DELETE"}`. Залиште один фільтр `Authentication` з параметрами `{}` і виберіть роль `ROLE_EXPERIMENT_WRITER`. Підтвердьте та збережіть.
5. Натисніть **«Опублікувати маршрути»**, потім **«Підтвердити публікацію»**. **Стоп секундоміра** — коли панель повідомить, що Gateway прийняв запит на оновлення. Запишіть час навіть у разі помилки та опишіть виправлення. За штатного проходження панель надсилає чотири запити зміни конфігурації та публікації разом. Обидві форми маршрутів зберігаються окремо. В автоматизованій REST-серії два маршрути передаються одним пакетним запитом.
6. **Після зупинки секундоміра** звірте рішення через Gateway. Перевірте чотири GET (список, деталі чинного товару, категорії, добірка) для гостя й обох користувачів. Перевірте POST, PUT і DELETE з коректним тілом там, де воно потрібне, і чинним ID для PUT/DELETE. Наприклад, створіть товар з унікальним іменем, наявним categoryId та ціною 15, а для PUT укажіть ціну 16. Зміни дозволені лише користувачеві з роллю. Використовуйте окремий тестовий товар, спочатку перевірте заборонені зміни, наприкінці деактивуйте товар уповноваженим користувачем та перевірте 404 за його ID. Запишіть правильність 21 рішення й коди відмов. Перед наступним повтором відновіть той самий порожній стан конфігурації на тестовій копії.
