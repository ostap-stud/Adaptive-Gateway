# Перевірка стенду від 25 листопада 2026 року

Базою була локальна копія Adaptive Gateway на Робочому столі, гілка `gateway-auth-develop`, коміт `408aee4` з наявними локальними змінами. Для перевірки використано наявні JAR основної системи з цієї копії. Прикладні JAR зібрано Maven 3.9.9 під JDK 21.0.10. СУБД — PostgreSQL 18.6, середовище — Windows. Взаємодія через Gateway відбувалася по локальному HTTP.

Прогін створив та прибрав власні дві БД і завершив запущені ним JVM. Автоматична браузерна перевірка відкривала готову React-збірку панелі на origin тестового шлюзу. Вхід і дані сторінки обслуговували реальні Gateway та Auth. Інтерактивного ручного обходу інтерфейсу не проводили.

### Як відтворити

1. З кореня проєкту виконайте `mvn -f research-stand/pom.xml package` або виберіть **Lifecycle → package** саме для research-stand у Maven-вікні IDEA. Для наскрізного тесту потрібні також готові JAR у `target` модулів `discoveryserver`, `auth-service`, `gatewayserver`, `adaptive-manager`.
2. Запустіть локальний тестовий PostgreSQL. Для автоматичного тесту потрібен користувач із правом створення БД. За парольної автентифікації передайте пароль через змінну середовища `PGPASSWORD`. Потрібні Python 3, `java`, `psql` і вільні loopback-порти 28761, 28334, 28088, 28335, 28911–28913. Імена двох БД генеруються для кожного прогону.
3. З кореня виконайте `py -3 research-stand/tests/acceptance.py --pg-port 5432 --pg-user postgres`. За потреби передайте повні шляхи параметрами `--java`, `--psql`. Для тесту використано готовий допоміжний модуль основного репозиторію `tools/verify-adaptive-cycle.py`. Звіти та локальні журнали з’являться в `research-stand/target/acceptance/`.
4. Щоб включити браузерну перевірку, додайте `--panel`. Потрібні готова збірка `admin-panel/dist`, Node.js, доступний для Node пакет `playwright` та встановлений Chromium або Edge. За потреби задайте `NODE_PATH` до каталогу пакетів і `STAND_BROWSER` з повним шляхом до браузера. Запуск без `--panel` перевіряє API адміністративної панелі.
5. Для ручного проведення використовуйте [порядок дослідів та порожню форму спостережень](EXPERIMENTS.uk.md). Налаштування PostgreSQL і ролей робочої інсталяції користувача виконуються окремо.

### Межі перевірки

Кнопки запуску IntelliJ IDEA та роботу з індивідуальними обліковими даними користувача вручну не перевіряли. Прогін S6 явно прибрав реєстрацію зупиненого екземпляра, щоб відтворити втрату реєстрації без очікування закінчення lease. Природний час виявлення аварійного завершення лишається окремим вимірюванням. Час адаптації, пропускну здатність і статистичні характеристики затримки в цій роботі не вимірювали.
